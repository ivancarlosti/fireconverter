# Internationalisation

FireConverter ships seven catalogs:

| Code | Language | Direction |
| :-- | :-- | :-- |
| `en-US` | English | LTR |
| `pt-BR` | Português (Brasil) | LTR |
| `es-MX` | Español (México) | LTR |
| `fr-FR` | Français | LTR |
| `h-CN` | 中文（简体） | LTR |
| `hi-IN` | हिन्दी | LTR |
| `ar-SA` | العربية | RTL |

The list is mirrored by `SupportedLocales` in `internal/handlers/system.go` and
the `LOCALES` array in `web/src/i18n/index.ts`.

## Runtime

- The choice is persisted in `localStorage['fireconverter.locale']`.
- With no stored value the browser languages are matched (with aliases such as
  `zh-CN → h-CN`, `en → en-US`).
- `applyDocumentLocale` sets `<html lang dir>`; `ar-SA` flips the document to
  RTL. Tailwind's custom `rtl:`/`ltr:` variants key off that attribute.
- Numbers use `Intl.NumberFormat`; byte sizes use decimal units (1 MB =
  1,000,000 bytes) to match target-size inputs.

## Catalogs

Files live in `web/src/i18n/locales/<code>.json`. They are nested objects:

```json
{
  "file": {
    "target": "Target size",
    "saved": "{percent} smaller"
  }
}
```

`createI18n` uses `flatJson: true` so both nested and dotted keys resolve. The
catalog is the single source of truth; no component hard-codes English copy.

Some keys are dynamic:

| Pattern | Values |
| :-- | :-- |
| `theme.<value>` | `light`, `dark`, `system` |
| `kind.<value>` | `image`, `audio`, `video` |
| `status.<value>` | `ready`, `uploading`, `awaiting`, `queued`, `converting`, `done`, `error`, `canceled`, `starting`, `pass1`, `pass2`, `encode`, `planning`, `engine`, `failed` |
| `errors.<code>` | every API/engine code plus UI-only codes |

If a code is missing, the store falls back to `errors.generic`; the checker
still requires the literal keys used by components.

## The checker

`web/scripts/check-i18n.mjs` runs before TypeScript in `npm run typecheck`:

1. every catalog must have exactly the keys of `en-US`;
2. every value must be a non-empty string without `TODO`/`FIXME`/`XXX`;
3. `{placeholders}` must match the reference;
4. every literal `t('key')`/`te('key')` used in `src/` must exist;
5. it reports keys used only dynamically (for visibility, not failure).

Run it alone with:

```bash
cd web
node scripts/check-i18n.mjs
```

## Adding a language

1. Copy `en-US.json` to `<code>.json`; translate every value, preserving
   placeholders.
2. Add the import, the `MESSAGES` entry and a descriptor (`code`, native label,
   `dir`) in `web/src/i18n/index.ts`.
3. Add the code to `SupportedLocales` in `internal/handlers/system.go`.
4. Add aliases if browsers report a different tag.
5. Run the checker and `npm run typecheck`.

## RTL notes

- Layout uses logical properties (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`),
  so most components mirror without changes.
- Numbers and file sizes carry the `numeric` class (`direction: ltr`).
- The theme's `rtl:` variant mirrors the switch thumb.
- The screenshots are captured in English/light; RTL is exercised by the
  language switcher with no extra build.

## Text in error messages

The UI translates the stable `code`; the server's English `error` string is
shown only as technical detail in the toast. This keeps translations useful
without hiding the encoder's reason.
